# Contributing to RBGraph

RBGraph welcomes improvements to the parser, diagram model, renderer, API, frontend, tests, and documentation.

## Workflow

1. Create a focused branch.
2. Make one logical change at a time.
3. Run `pytest` before opening a pull request.
4. Keep public behavior documented.
5. Use clear commit messages.

## Pull requests

Explain what changed, why it changed, and how it was tested. Screenshots are useful for visible frontend changes.

## Code style

Prefer small functions, explicit data models, readable names, and predictable API responses. Keep security-sensitive input escaped and validated.
